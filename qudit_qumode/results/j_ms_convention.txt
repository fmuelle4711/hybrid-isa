========================================================================================================
2  ALGEBRA: DOES ONE MS WINDOW GENERATE XX+YY ?
========================================================================================================

  A Molmer-Sorensen window with phase phi generates
      U_MS(theta, phi) = exp( -i theta  sigma_phi (x) sigma_phi ),
      sigma_phi = cos(phi) X + sin(phi) Y.
  Expanding the product:
      sigma_phi (x) sigma_phi
        = cos^2(phi) XX + sin^2(phi) YY
        + cos(phi)sin(phi) (XY + YX).
  For this to equal (XX + YY)/1 the cross terms must vanish and both
  squared coefficients must be 1 simultaneously:
      cos(phi)sin(phi) = 0   ->  phi = 0 or pi/2
      phi = 0    ->  XX only
      phi = pi/2 ->  YY only
  There is NO phi giving XX + YY. One window yields ONE quadrature product.

  Two windows suffice, and exactly, because XX and YY COMMUTE:
      (X(x)X)(Y(x)Y) = (XY)(x)(XY)
      (Y(x)Y)(X(x)X) = (YX)(x)(YX) = (-XY)(x)(-XY) = (XY)(x)(XY)
      => [X(x)X, Y(x)Y] = 0
  hence
      exp(-i theta (XX+YY)) = exp(-i theta XX) exp(-i theta YY)
  is an IDENTITY, not a Trotter approximation. No splitting error.

  Convention followed: Molmer-Sorensen as in pulses_meth/docs/sdf_zbasis.md
  (sigma_phi (x) sigma_phi). Meth's 200 us is quoted for that gate
  (appendix_table.md: 'Molmer-Sorensen entangling gate on two ions',
   Meth SI Note II p.3, 0.2 ms per gate, angle-independent).

  CAVEAT: a native XY / exchange interaction WOULD do it in one window,
  but nothing in this repo or in the Meth anchor claims such a gate.
  Meth quotes an MS time, and this repo defines MS as sigma_phi(x)sigma_phi.

========================================================================================================
3  VERDICT
========================================================================================================

  H_J costs TWO MS windows per pair per application, i.e. 2 x 200 us.

  Reasons: one window gives only sigma_phi(x)sigma_phi (section 2);
  XX and YY commute so two windows are exact; and the repo's own
  circuit code already emits IsingXX and IsingYY separately (1c).
  The single contrary statement is docs/audit_trotter.md:78, which is
  a prose label rather than emitted code.

  NOT settled here, and deliberately left alone: H_Jl.
    H_Jl = g_abl*(sxa*sxb + sya*syb)*xl/2 + g_acl*(...)*xl/2
  carries the same XX+YY structure but multiplied by x_l, so it is a
  3-body term realised via CD sandwiches, not by bare MS windows. Its
  200 us pricing was already flagged as a CHOICE in
  results/gate_count_reconcile.txt and is held fixed below so that only
  ONE variable changes.

========================================================================================================
5  SUMMARY
========================================================================================================
1. H_J needs g(XX+YY)/2 per pair; one MS window gives only
   sigma_phi(x)sigma_phi, and no phi yields XX+YY. VERDICT: 2 windows.
2. Two windows are EXACT, not approximate: [XX, YY] = 0, so
   exp(-i t (XX+YY)) = exp(-i t XX) exp(-i t YY) identically.
3. MS windows per qubit step: 6 published -> 10 under the verdict (+4), i.e. T_qubit 1596.1 -> 2396.1 us.
4. Ratios move in the qudit's favour: sequential [3.82, 4.03] -> [5.73, 6.04]; parallel-MS [2.38, 2.51] -> [3.34, 3.52]. Published numbers are the conservative ones.
5. OPEN: docs/audit_trotter.md:78 calls XX+YY one 'combined' gate,
   contradicting this. And H_Jl's 200 us pricing is still an unexamined
   CHOICE - it was held fixed here so only one variable moved.
